# Лендинг «Профессия DJ с нуля» — DJ KIDY

Одностраничный лендинг онлайн-курса Кирилла «DJ KIDY». Эталон дизайна — основная платформа
клиента **`https://new.areyoukidy.me/`**: у лендинга и платформы должен быть один визуальный язык.

Весь CSS референса лежит инлайном в единственном `<style>` на главной (~505 КБ). Токены ниже
сняты из его `:root` и подтверждены замерами `getComputedStyle` на ширинах 1920 и 1440 —
**это точные значения, а не глазомер**. Ходить на референс повторно за цифрами не нужно:
источник правды по дизайну — этот файл.

## ⚠️ Правила этого проекта переопределяют правила репозитория

Общий `Lendosi/CLAUDE.md` (Tailwind CDN, один файл, минимум токенов, «NO YAPPING») здесь
**НЕ действует**. Для `DJ/` правила такие:

1. **Всегда подробно рассказывать, что делаешь:** перед каждым шагом (команда, правка файла,
   скриншот, диагностика) — объяснять простым языком, что это за действие, зачем оно нужно
   и что даст. Особенно для вспомогательных/технических команд (обработка картинок, установка
   утилит, отладка) — их назначение неочевидно, проговаривать обязательно.
2. **Стек:** чистые HTML + CSS + vanilla JS. Никаких фреймворков (React/Vue/Nuxt), сборщиков,
   npm и Tailwind. Никаких CDN-библиотек и CDN-шрифтов, кроме случая, если клиент явно попросит
   (аналитика, платёжки, карты). Шрифт self-hosted.
3. **Файлы по блокам:** у каждого блока страницы свой CSS-файл; у блоков с поведением — свой
   JS-файл. Всё подключается напрямую в `index.html`: CSS через `<link>`, JS через
   `<script defer>`. Без импортов, без сборки.
4. **Кастомный CSS писать можно и нужно** — это основной инструмент стилизации.
5. Ответы и код — без ограничений на «минимум токенов»: приоритет — точное соответствие
   дизайн-системе референса.

## Дизайн-система

### Палитра — перенесена с референса 1:1, править нельзя

Требование клиента: «цвета как в референсе строго». Все значения объявлены в `css/base.css`
как «сырые» переменные бренда, поверх них — семантический слой по темам.

```
Бренд     --primary100 #F2F5FF   --primary200 #7D81FF   --primary300 #5359FF   --primary400 #292B66
Статусы   --success    #42D819   --error      #FF5356   --warning    #FF9030
Тёмные    --backgroundDark #15161A  --dark400 #0F0F12  --dark300 #232325
          --dark200 #303136         --dark100 #44464C
Светлые   --backgroundLight #F4F7FB --gray100 #F5F6F7  --gray200 #F0F0F0
          --gray300 #E7E7E7         --gray400 #AFAFAF  --gray500 #838792
Оверлеи   --blackOverlay rgba(0,0,0,.3)   --whiteOverlay rgba(255,255,255,.15)
Радуга    --key1A…--key12A: #42D819 #32E69E #28E7D7 #53D7FF #53A0FF #5359FF
          #7853FF #AF53FF #FC53FF #FF5398 #FF5356 #FF9030
```

Ряд `key1A…key12A` — это цвета камелот-ключей из плеера платформы. На лендинге они не нужны
поштучно, но заведены целиком: из них берутся акценты для бейджей и декора, чтобы случайные
оттенки не появлялись.

### Геометрия и типографика по ступеням

Брейкпоинты референса: **1600 / 1480 / 1024**. Плюс наши **768 / 576** для раскладок,
которых у него нет (у него это внутренние страницы платформы, у нас — лендинг).

| токен | >1600 | 1025–1600 | ≤1024 |
|---|---|---|---|
| `.container` max-width | 1488 | 1304, с 1480 → 1116 | 100%, поле 16 |
| card `--radius` / `--padding` | 40 / 40 | 32 / 32 | 24 / 24 |
| section `--padding` / `--main-margin` | 40 / 100 | 32 / 80 | 24 / 60 |
| `.section__title` | 42 | 36 | 26 |
| `.card__title` | 44 | 32 | 26 |
| `.section__text`, `.card__text` | 20 | 16 | 16 |
| `.btn-lg` padding / fs / radius | 24 32 / 20 / 24 | 16 24 / 18 / 16 | то же |
| card `--translate` (ховер-подъём) | 12 | 12 | 0 |

Постоянные величины (одинаковы на всех ширинах):

- `.btn` — `padding 16 24`, `radius 16`, `font-size 18`, `font-weight 500`;
  `.btn-sm` — `padding 12 24`.
- Шапка-капсула — `radius 24`, `padding 16 16 16 24`, поле страницы вокруг неё `8`.
- Пилюли, бейджи, аватары, кружки стрелок — `border-radius: 96px` (полная скругляшка;
  на референсе это `6rem`, используется как «сделай круглым», а не как настоящий радиус).
- Кружок стрелки слайдера — `48×48`, фон `--card-bg`.
- `--gap` секции — `24`, гуттер сетки — `8`.
- Заголовки `h1–h6` — `font-weight: 600`, `line-height: 100%`.
- Теней почти нет: контраст держат `--main-bg` и `--card-bg`. Единственная используемая —
  `0 4px 5px 0 rgba(0,0,0,.03)` на бегунке тумблера темы.

### Шрифт

**Inter**, self-hosted в `assets/fonts/inter/` (сабсеты `cyrillic` и `latin`, woff2).
Начертания: 400 (текст), 500 (кнопки, ссылки), 600 (заголовки). Подключается через `@font-face`
в `base.css`, `font-display: swap`.

### Моушен — две подписи, не смешивать

**Слой UI** — всё, что отвечает на действие пользователя. Кривая и длительность взяты
с референса, у него они единые на весь сайт:

```
--ease: cubic-bezier(.7, .54, 0, .74);
--dur:  .3s;
```

Ховеры, табы, аккордеоны, инпуты, смена темы — только эти значения.

**Слой ритма** — всё фоновое и декоративное. Кратно биту 128 BPM:

```
--beat: 468.75ms;                  /* 60000 / 128 */
--bar:  calc(var(--beat) * 4);     /* такт, 1875ms */
```

Эквалайзер, пульс точки дедлайна, дрейф градиента в hero, скорость бегущей строки, счётчики.
Общий делитель — то, ради чего это сделано: страница читается как один живой организм,
а не как набор случайных твинов.

⚠️ **Любая новая анимация обязана лечь в один из двух слоёв** и **обязана глушиться**
в `@media (prefers-reduced-motion: reduce)`. Ритмический слой там отключается целиком,
от UI-слоя остаётся только смена цвета.

## Конвенции кода

### HTML
- Семантика: `header` / `main` / `section` / `footer`; каждой секции — `id` для якорей меню.
- Порядок секций в `index.html` = порядок в таблице блоков ниже.
- Изображения ниже первого экрана — `loading="lazy"`; в первом экране — без него.

### CSS
- Классы БЭМ-подобные с префиксом блока: `.hero__title`, `.program__tab--active`, `.faq__item--open`.
- **Все цвета, радиусы, шрифты, кривые и длительности — только через переменные из `base.css`.**
  Хардкод хекс-кодов и `cubic-bezier(...)` в файлах блоков запрещён.
- Медиазапросы каждого блока живут в его же CSS-файле, внизу, по убыванию ширины.
- Верстаем сверху вниз: сначала >1600, затем ступени 1600 / 1480 / 1024 / 768 / 576.
- Высоты не фиксируем: при переливе текста блок должен расти, а не обрезать содержимое.
  `min-height` — это пол, а не размер.

### JS
- Vanilla, ES2015+, без зависимостей. Один файл = один блок.
- Каждый файл самодостаточен: находит свой корневой элемент по классу блока, если его нет
  на странице — тихо выходит. Оборачивается в IIFE.
- **Контент живёт в разметке, а не в массивах JS.** Модули тарифов, отзывы и вопросы FAQ
  лежат в `index.html`; JS только переключает состояния. Это лендинг: текст должен быть
  виден поисковику и читаться при отключённом JS. Данные в JS-файле заводим, только если
  их без скрипта не существует (например, значения таймера).
- Глобальны только явные хелперы из `main.js`.

### Типографика русских текстов
Неразрывный пробел после коротких предлогов и союзов, между числом и словом («2 года»,
«8 лет»), в сокращениях. Тире в предложении — `—`, диапазоны — `–`, кавычки — только
«ёлочки». Тексты ёфицированы. Цены — с неразрывным пробелом в разряде: «20 000 ₽».

⚠️ **Где какой символ:** в `index.html` — сущность `&nbsp;`; **в данных JS — литеральный
U+00A0**, потому что часть строк вставляется через `textContent`, и сущность вывелась бы
как текст. В редакторе такой пробел неотличим от обычного — в шапках таких файлов стоят
предупреждения.

⚠️ **Кеш.** Параметр в адресе (`index.html?v=2`) обновляет только саму страницу — CSS и JS
подтягиваются из кеша по прежним URL, и правка «не работает». Для CSS помогает перевесить
`href` у `<link>`. Для JS этого приёма нет: повторная вставка `<script>` запустит IIFE второй раз
и продублирует обработчики. Надёжный способ — поднимать сервер, который сам запрещает кеш
(`SimpleHTTPRequestHandler` + `Cache-Control: no-store` в `end_headers`).

⚠️ Скриншоты Playwright по умолчанию падают в корень проекта и в `.playwright-mcp/` —
после проверки удалять.
